# Практична робота №10. Командна робота з Git та GitHub (Workflow)

## 1. Стратегія гілкування (Branching Strategy)
У проєкті застосовується модель **Git Flow / Feature Branch Workflow**:
* **`main`** — стабільні робочі версії проєкту (релізи).
* **`development`** — основна гілка для інтеграції нового коду.
* **`feature/*`** — окремі гілки під розробку конкретних задач (наприклад, `feature/game-over-logic`, `feature/coins-system`).

## 2. Процес створення Pull Request (PR)
1. Створення нової гілки від `development`:
   ```bash
   git checkout -b feature/fall-death-logic
   ```
2. Внесення змін у C# скрипти (`BirdScript.cs`), додавання тригера `DeathZone`.
3. Коміт та push гілки у віддалений репозиторій:
   ```bash
   git add .
   git commit -m "Реалізовано перевірку зіткнення з зоною падіння DeathZone"
   git push origin feature/fall-death-logic
   ```
4. Відкриття **Pull Request** у GitHub з гілки `feature/fall-death-logic` в `development`.
5. Проходження **Code Review** іншими учасниками команди, розв'язання конфліктів (Merge Conflicts) та схвалення PR.
